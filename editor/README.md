# 场景编辑器

在网页里画路、楼、绿地水面、店门和出入口，点一下就生成场景并在仿真里打开。

## 目录

| 路径 | 内容 |
|---|---|
| `index.html` | 页面入口，开发服务器地址 `/editor/` |
| `src/EditorApp.vue` | 界面：画布、工具栏、属性面板、生成 |
| `src/model.js` | 纯逻辑：场景拆成矢量图、命中测试、吸附、生成前检查 |
| `backend/drawscene.py` | 矢量图 → 标记图 + sidecar → `tools/map2scene.py` |
| `tests/` | 前端 `editor.test.js`（vitest）和后端 `test_drawscene.py`（pytest） |

导入服务 `tools/sat_server.py` 的 `POST /api/draw/build` 调用后端。运行测试：

```bash
npx vitest run editor/tests
python -m pytest editor/tests -q
```

## 用法

- **打开方式。** 在三维页的调试条点「编辑场景」，会在当前场景上打开编辑器。也可以直接访问 `/editor/` 从空白画布开始。需要运行导入服务 `python tools/sat_server.py`。
- **画路。** 沿中心线点几下，双击或按回车结束。每条路可以设每方向车道数（1 到 4 条）、单行和高架。单行路按画的方向行驶。端点靠近已有道路时会自动吸附，接上就是一个路口。按住 Shift 可以取 45° 整数倍方向。
- **画楼和区域。** 点出轮廓，双击闭合。楼有商铺、写字楼、住宅、场馆四种，可以填层数。区域有绿化带、公园、水体、广场、停车场。
- **店门和出入口。** 店门会自动贴到最近的外墙。不标的话，生成时会自动布。
- **路口。** 用路口工具点在路口中心，可以设有没有红绿灯、东西向和南北向各自的绿灯时长、禁止左转。不设置的路口按默认配灯，两个方向各 22 秒。
- **场馆。** 场馆类型的楼可以填名称、类型（体育场、剧院、通用）和容量，需求模型按它排活动。
- **修改。** 选择工具可以点选元素改属性、拖顶点改形状，Delete 删除，Ctrl+Z 撤销。改动会自动存在本机。
- **底图。** 可以选一张本地卫星图或截图铺满画布，对着描。在导入场景上打开时，会带上原来的卫星图和经纬度。
- **生成。** 编辑器把矢量图交给 `editor/backend/drawscene.py`，画成和手工标记一样的标记图，再交给 map2scene。路口、斑马线、红绿灯、人行道、行道树都自动生成。车道数和单行方向通过 sidecar 传给 map2scene，前端按指定的车道数排车道。
- **在已有场景上改。** 楼的编号、场馆信息、实地标注写回的商户和吸引力、店门位置、路口设置都会带上，重新生成后保持不变。被路口切开的路段会接回整条。
- **提醒。** 高架端点停在画布中间、路口设置附近没有路口时，右侧会给黄色提醒，但不挡生成。
- **命名。** 编辑器生成的场景存成 `imported/<场景名>`，旁边另存一份矢量图，下次打开和上次画的一模一样。在别的场景上改时，场景名默认加 `-edit`，不会覆盖原场景。


## 生成是怎么做的

编辑器画的是矢量图：路是中心线加属性，楼和区域是多边形，店门、出入口、路口设置是点。

生成时 `backend/drawscene.py` 把矢量图画成标记图，颜色和手工标记完全一样，再交给 `tools/map2scene.py`。路网骨架、路口归正、斑马线、红绿灯、人行区域、行道树、停车位都由 map2scene 生成，和其他来源的场景行为一致。

标记图表达不了的信息走 sidecar 附加文件：

| 字段 | 内容 | map2scene 怎么用 |
|---|---|---|
| `footprints` | 每栋楼的轮廓、类型、层数、编号和属性 | 直接当楼，编号沿用，属性原样写进场景 |
| `roads` | 每条路的中心线、路宽、每方向车道数、是否单行 | 按几何重合对到骨架提取出的道路边上 |
| `junctions` | 路口设置的位置和内容 | 对到附近最近的平面路口节点上 |

前端读场景时：车道排布按道路边上的 `laneCount`，信号灯按节点上的 `control` 和 `signal`，车流选路时按 `noLeft` 去掉左转。

## 限制和下一步要考虑的

### 这一轮已经解决的

| 原来的限制 | 现在 |
|---|---|
| 重新生成后楼的编号全变，实地标注的数据对不上 | 编号沿用；重复或缺失的编号从没占用的号里补 |
| 实测店门、场馆信息、商户清单在重新生成时丢失 | 全部随矢量图带上，原样写回场景 |
| 信号灯全局固定配时，不能关灯 | 每个路口可以关灯、分别设两个方向的绿灯时长、禁止左转 |
| 自动导入的路网被路口切成碎段，不好改 | 打开时把直直穿过路口、属性相同的路段接回整条 |
| 高架停在画布中间时车会凭空消失，没有任何提示 | 编辑器给出提醒 |

### 还没解决的，以及各自要考虑什么

**1. 高架落地（引桥）。** 现在高架只能两端都通到画布边上。
- 渲染要支持带坡度的桥面。现在的桥面是固定标高的平板。
- 车流要把高架末端接到它落地的那条地面路上，相当于一种新的匝道，而且落地段不能压着斑马线。
- map2scene 要识别出停在画布内的高架端点，并找到它落地的地面路。编辑器里可以让用户标出落地端。

**2. 逐进口道的导向车道（左转、直行、右转箭头）。**
- 生成前编辑器并不知道路口有几个进口道，因为路口是 map2scene 从标记图里算出来的。
- 可行的办法有两个。一是在编辑器里自己算路网拓扑。二是先生成一次，再在生成出来的路网上编辑进口道。
- 数据上要给每条道路边的两端加车道用途，比如 `["L", "S", "SR"]`。车流按它选车道，路面画导向箭头。

**3. 多相位信号（左转专用相位、行人专用相位）。**
- 现在的信号灯只有两个轴轮流放行。要改成每个路口一张相位表，每个相位写明放行哪些方向和时长。
- 车流的冲突判断也要跟着改：有左转专用相位时，左转车不用再找对向直行的空档。
- 编辑器里需要一个相位时间轴的编辑界面。

**4. 路口形状和渠化（转角半径、右转渠化岛）。** 这些现在由骨架和路宽自动决定，栅格流程里没有地方表达。

**5. 栅格中转的精度上限。** 这是上面 2 到 4 的根源。
- 矢量图先画成 0.25 米每像素的标记图，再骨架化。路口位置会偏几米，道路边会被切碎，匹配车道数时要靠几何重合，重合不到 60% 的短边就用路宽推。
- 彻底的办法是矢量原生生成：直接由画的中心线建路网，路口几何、车道截断、斑马线都在矢量上算。
- 代价是要把 map2scene 里六百多行路网逻辑用矢量方式重写一遍。建议先做「生成后回显」：把生成出来的路网叠回编辑器，让用户看到哪里没对上，再决定要不要重写。

**6. 多人编辑和版本。**
- 同名场景后生成的会直接覆盖，矢量图也只存最新一份。
- 需要保留历史版本，最简单的做法是生成时把旧的 `_drawing.json` 按时间归档。
- 多人同时改一张图时，需要锁或者像实地标注那样按元素合并。

**7. 大场景性能。**
- 画布用 SVG，几百栋楼没问题。上千栋楼时要换 Canvas 或 WebGL 渲染，点选要加空间索引。
- 标记图长边上限 4000 像素，2 公里以上的画布会降到每像素 0.5 米以上，窄路可能画不出来，需要分块生成。

**8. 和实地标注的关系。** 编号现在稳定了，但删掉或拆分一栋做过实地标注的楼时，挂在旧编号上的商户会变成孤儿。需要在删除或拆分时提示，并能把商户改挂到新楼上。

**9. 空白画布的地理位置。** 从空白画布画出来的场景没有经纬度，手机定位用不了。可以加一个「定位画布」的功能：在底图上点两个已知经纬度的点。
